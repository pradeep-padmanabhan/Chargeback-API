# ADR-0125: Case reference generation

Status: **Accepted in full (2026-09-29)**: global sequence, no yearly reset, UTC year · Date: 2026-09-29

## Decision (accepted)
`CB-{YYYY}-{zero-padded 6-digit sequential number}`, for example `CB-2026-000001`. The number is generated by the database.

## Implementation
- **Sequence:** migration 0003 creates `chargeback_diagram.case_reference_seq` (`MINVALUE 1 MAXVALUE 999999 NO CYCLE`).
- **Allocation:** each case takes `nextval()` when it is created by the case-creation workflow.
- **`{YYYY}`:** the **UTC** year at creation, because the calendar time zone is not approved (ADR-0122).
- **Uniqueness:** `cases.case_reference` is UNIQUE (baseline).
- **Gaps:** PostgreSQL sequences are not transactional. A rolled-back creation, or a duplicate event that loses a race, consumes a number, so references are **increasing but may have gaps**.
- **Capacity:** after 999,999 references, `nextval` fails. Case creation then reports `CASE_REFERENCE_CAPACITY_EXHAUSTED` and the event is retried. The platform never silently changes the format, for example by adding a seventh digit.

## Questions
1. **Does the number reset every year** (`CB-2027-000001`)? The single global sequence implemented here does **not** reset, so its capacity is 999,999 cases **in total**. A yearly reset would need a sequence per year or a counter table, which is a schema decision.
2. **The time zone for `{YYYY}`,** which matters for cases created around New Year.
3. **Are gaps acceptable** (auditors sometimes expect gap-free numbering)? Gap-free numbering needs a locked counter row, which serializes case creation.

## Decision on the questions (2026-09-29)
1. **No reset:** a single global sequence, so the capacity is 999,999 cases in total. Beyond that, creation fails loudly with `CASE_REFERENCE_CAPACITY_EXHAUSTED`, never with a changed format.
2. **The year is the UTC year of creation.**
3. **Gaps:** no gap-free requirement was stated, and this implementation may have gaps. Please confirm if auditors require gap-free numbering.
